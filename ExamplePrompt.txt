The format of the card is JSON. Since it's JSON, I will describe the keys, ranges, descriptions, etc. as something like `"key": FLOAT - RANGING FROM 1 THROUGH 5 DOING XYZ`. You start the file with its metadata:
```json
    "class": "STRING - WHATEVER CLASS/GENRE THIS IS; E.G., GEOMETRY",

```

Categories require a further explanation. Categories can be either specific subsections, chapters from a whole, or something more general (like, "Definitions," "The End of WW2," "The Battle of Bunker Hill"). Later, in the cards, you refer to these categories by index. Categories are not required, but are useful for organization.

Next up are the cards. A Card is a specially formatted JSON within an array. The format is:
```json
"cards": [
    ...
    {
        "randomizedFront": BOOLEAN - WHETHER THE FRONT IS AN ARRAY WHERE A SPECIFIC ELEMENT IS CHOSEN TO REPRESENT THE FRONT RANDOMLY. THIS IS USEFUL FOR TERMS THAT HAVE DIFFERENT TERMINOLOGY BUT THE SAME DEFINITION.,
        "category": INT - SPECIFIC CATEGORY INDEX. 0 IS NO CATEGORY,
        "explanation": "STRING - OPTIONAL TEXT THAT CAN BE OPTIONALLY READ ON THE BACK SIDE OF THE CARD",
        "hint": "STRING - OPTIONAL TEXT THAT CAN BE OPTIONALLY READ ON THE FRONT SIDE OF THE CARD",
        "front": "STRING - FRONT SIDE",
        "back": "STRING - BACK SIDE",
        "difficultyWeight": FLOAT/NULL - NUMBER RANGING FROM 0 TO 5 IN INCREMENTS OF 0.5 REPRESENTING THE DIFFICULTY; 0 IS EASY, 5 IS HARD. NULL IF UNSPECIFIED. 
    },
    ...
]
```

The Front and the Back are both HTML. Meaning, you can use simple HTML styling, like <i>italics</i> or <b>bold</b>. While all tags are supported, you should keep to simple style-related ones. CSS and JS also work via <style> and <script> tags.
